# Content Guide

図解コンテンツを生成する直前に読む。`references/base.html` と `references/model-answer.html` を見たうえで、本ファイルのルールと表現パターンに従う。

## 目次

- 守ること
- 説明の組み立て方
- ビジュアルの使い分け
- ページ構成
- 出典と言語

## 守ること

- **React・shadcn/ui を使わない** — 静的な図解に JS フレームワークは不要
- **絵文字を使わない** — OS 依存で表示が変わる。アイコンは Lucide Icons を使う
- **インタラクティブ要素を入れない** — トグル、フォーム、クリック開閉、アニメーションは禁止
- **`<style>` タグを追加しない** — スタイリングは Tailwind CSS クラスで行う。インラインの `style` も避ける
- **`<script>` を追加しない** — テンプレートに含まれるもの以外の JavaScript は使わない
- **外部リソースを追加しない** — テンプレートに含まれる読み込み以外の画像 URL、フォント、追加 CDN は使わない
- **テンプレートの額縁構造を変更しない** — `<head>`、meta、既存 CDN はそのまま維持する
- **PDF 印刷で消える表現を避ける** — `bg-clip-text text-transparent` のグラデーション文字は印刷時に消えやすい

## 説明の組み立て方

- **概論から各論へ進む** — いきなり詳細に入らず、まず全体像を見せる
- **専門用語は初出で解説する** — 括弧書きで平易な言い換えを添える
- **身近なたとえを使う** — レストラン、郵便、信号機など既知の体験に結びつける
- **たとえ話もできるだけ図にする** — テキストだけで済ませず、ミニビジュアル化を検討する
- **簡潔にしすぎない** — 理解に必要な情報量は削らず、腹落ちするまで説明する
- **図を先に見せる** — 見出しから最初のビジュアルまでのテキストは最大 2 段落までに抑える
- **見たことがあるものは再現して見せる** — UI や画面に言及するときは文章だけで済ませず、Tailwind CSS でミニ再現する

## ビジュアルの使い分け

ビジュアルには **構造を示す図** と **体験を再現する図** の 2 役がある。どちらか一方ではなく、両方を組み合わせて使う。

### 構造を示す図

- **定義を説明する** → アナロジー図。主役を中央に置き、身近なたとえの登場人物と関係線で示す
- **プロセスを説明する** → ステップフロー。番号つきで並べ、各ステップにアイコンと短い説明を添える
- **違いを説明する** → 左右対比。同じ観点を同じ行に揃え、色や記号で差を一目で見せる
- **具体例を並べる** → カードグリッド。アイコン、タイトル、短い説明を揃える
- **数値の強みを見せる** → 数字カード。大きい数字を主役にし、色で役割を分ける
- **構造や中身を見せる** → 入れ子ブロック。外側と内側の階層を背景色やボーダーで示す
- **誤解を正す** → 誤解と正解の対比カード。赤と緑で切り替える
- **変遷を見せる** → タイムライン。時点と要約を縦または横に並べる

### 体験を再現する図

- **チャット UI** — 吹き出し、左右の話者、入力欄モック
- **エディタ UI** — タイトルバー、サイドバー、コードペイン、必要なら AI パネル
- **ターミナル UI** — タイトルバー、プロンプト、コマンド、出力
- **ブラウザ UI** — タイトルバー、アドレスバー、ページ内容
- **アプリ画面** — 天気、地図、決済などのミニモック

共通ルール:

- リアルすぎる再現より、要点が伝わる最小限の再現を優先する
- 特定ブランドのロゴや名称は避け、汎用的な表現にする
- Tailwind CSS クラスのみで構成する

## ページ構成

- **冒頭にヒーローと一枚絵サマリーを置く** — タイトル直後に「ひとことで言えば」の答えとコア図解を見せ、その後で各論に入る
- ヒーローは **一言の答え → 図 → 各論への橋渡し** が一本の流れになるように組む
- 一枚絵サマリーには少なくとも次を含める:
  - **一言の答え** — トピックの核心を 1 文で示す
  - **コア図解** — その 1 文をアイコンや矢印で視覚化する
  - **身近な接点** — 読者が経験済みの例を 2〜4 個並べる
- **読者レベルをラベル化しない** — 「初心者向け」「入門」などはタイトル、見出し、本文に入れない
- **ヒーローバッジはカテゴリにする** — テクノロジー、ビジネス、開発ツールなど、トピックの種類を示す

## 出典と言語

- 検索結果から採用した事実、定義、数字の近くにインライン出典を置く
- 出典リンクは本文を邪魔しない位置に置き、`text-xs text-ads-dim` で小さく薄く見せる
- リンクテキストは URL そのままではなく、何の出典か分かる名前にする
- 英語メインのトピックでも、図解本文は日本語で書く
