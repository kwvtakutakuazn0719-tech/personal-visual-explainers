# Publishing Guide

公開、既存 HTML の再公開、図解の削除、完了報告が必要になった時点で読む。Node.js がない場合だけ `node-install-guide.md` を追加で読む。

## 公開・削除時の選択（必須）

**自由記述だけで対象ファイルや teardown 対象を決めない。** 先にツールで候補を把握し、**AskQuestion**（または同等の明示選択）でユーザーが範囲を確定してからコマンドを実行する。

### 既存 HTML を公開するとき

1. ワークスペース基準で **`output/**/*.html`** を列挙する（`.git` / `node_modules` は除外）。**0 件なら**「公開候補となる HTML が見つかりませんでした」と伝えて **終了**。推測で surge しない。
2. 候補に **パスと最終更新日時**（分かる範囲）を添えて示す。
3. **一括公開禁止**: ユーザーが選んだ **1 件または明示スコープ内**にだけ `surge` / `deploy-diagram.sh` を使う。選ばれていないファイルに対して実行しない。
4. 候補が多すぎるときは、先に **AskQuestion** で絞る（例: 先頭から最大 8 件だけ選ぶ／`yyyy-mm-dd` の開始・終了で更新日時を絞る／中止）。

### Surge の公開を削除（teardown）するとき

1. **`deploy-history.log`** を読み、行から URL を抽出する。形式が `YYYY-MM-DD HH:MM:SS | URL` のときは日時で範囲指定に使える。**ログが空または URL が 0 件なら**「削除対象の URL をログから特定できませんでした」と伝え、必要ならユーザーに URL の明示を求めて **終了**。推測で teardown しない。
2. **AskQuestion** で削除の単位を必ず選ばせる。例:
   - **単一 URL** を一覧から選ぶ（件数が多いときは日付で先に絞る）
   - **日付範囲**（ログタイムスタンプが `yyyy-mm-dd` で解釈できる行に限定）→ 該当 URL を一覧表示 → **実行する／中止**の最終確認
   - **ログ記載の URL 全件** teardown（**必ず**「本当に全件か」の確認を挟む。取り消しが効きにくいため）
   - **中止**
3. 確定したドメインに対してのみ `npx surge teardown [ドメイン]` を実行する。

## 新規公開

1. まず Node.js の有無を確認する

```bash
node --version
```

- バージョン番号が表示された → そのまま公開へ進む
- `command not found` などで失敗した → `node-install-guide.md` の手順に従って案内する

2. 生成済みの `output/{スラッグ}.html` を公開する

- **macOS / Git Bash（Windows）**:

```bash
bash .claude/skills/creating-visual-explainers/scripts/deploy-diagram.sh output/{スラッグ}.html [スラッグ]
```

- **Windows PowerShell で bash が使えない場合**:

```powershell
npx --yes surge output/{スラッグ}.html --domain diagram-[スラッグ].surge.sh
```

`[スラッグ]` にはトピックに関連する短い英単語を使う。

## 既存 HTML の再公開

既存の HTML を公開したい依頼では、図解生成は行わず、**上記「公開・削除時の選択（必須）」の「既存 HTML を公開するとき」**を先に実行してから、ユーザーが選んだ対象にだけ上の「新規公開」と同じコマンドを使う。

- スラッグ指定がなければ、ファイル名から短く自然な英単語スラッグを決める
- 完了報告は「新規公開」と同じテンプレートでよい

## 図解の削除

**上記「公開・削除時の選択（必須）」の「Surge の公開を削除（teardown）するとき」**に従い、スコープ確定後にのみ次を実行する。

1. 対象ドメインを確定する（単一・日付範囲・全件はいずれも **AskQuestion で明示確定済み**であること）
2. ドメインごとに削除する

```bash
npx surge teardown [ドメイン]
```

3. 削除完了を短く伝える

## 初回登録とエラー対応

### 初回登録

Surge 未登録なら、ターミナルにメールアドレスとパスワードの入力を求められる。以下を伝える:

> 初回のみアカウント登録が必要です。  
> メールアドレスを入力して Enter → パスワードを決めて入力して Enter。  
> 確認メールが届いたらリンクをクリックすれば登録完了です。  
> 次回以降はこの手順は不要です。

### エラー対応

エラーメッセージはそのまま投げず、**何が起きていて、次に何をすればよいか** を平易に説明する。

よくあるエラー:

- **`npx: command not found`** — Node.js がまだ使えない。`node-install-guide.md` の手順を案内する
- **`surge: not found` / surge 関連エラー** — `npm install -g surge` を実行してから再試行する
- **認証エラー / `Login required`** — `npx surge login` を実行してログインする
- **その他** — 問題点と次の一手を専門用語なしで説明する

## 完了報告テンプレート

### 公開に成功した場合

```
完成・公開完了: 【図解のタイトル】

（図解の内容を1〜2文で要約）

公開URL:
https://diagram-スラッグ.surge.sh

図解の主なポイント:
- （主要トピックを3〜5個）

この図解を削除したいとき:
チャット欄で「この図解を削除して」と伝えてください。
```

### 公開できなかった場合

```
完成: 【図解のタイトル】

（図解の内容を1〜2文で要約）

ファイルの保存先:
output/{スラッグ}.html（ブラウザにドラッグ＆ドロップすると表示できます）

図解の主なポイント:
- （主要トピックを3〜5個）

URLで共有したいとき:
チャット欄で「この図解を公開して」と伝えてください。
```
