# プロダクト名 SEO / AEO ルーブリック（正本）

`../SKILL.md` から参照。Shopee 内部アルゴリズムの断定は書かない。**一般の情報検索・エージェント購買**の観点に限定する。

## 用語

### SEO（本スキルでの意味）

人間またはシステムが **キーワード・型番・ブランド** で検索したとき、クエリとタイトルの **語の重なり・順序・冗長性** が合理的であること。目的は「検索エンジンの内部仕様に当てる」ではなく、**意図と文面の対応が読み取りやすい**こと。

### AEO（本スキルでの意味）

「スニペットに載りやすい」だけに限定しない。**今後、AI／エージェントが検索・比較・購入判断を代行する**場面を想定し、タイトルが **自動判断者の信頼度（confidence）を上げやすい**表現であること。具体的には次の **機械可読な誠実さ** を指す。

- **同一商品の識別**: ブランド・モデル（シリーズ）・品目が、別 SKU や別カテゴリと **誤結合しにくい**並びになっているか。
- **検証可能性**: 調査ソースに現れない誇大・曖昧修飾・無関係な流行語の詰め込みがないか。
- **誤購入リスク**: 用途・素材・性別などの語が **誤解を招く共起**になっていないか（エージェントが「この注文で合っているか」を判定しやすいか）。

SEO と AEO は対立させない。**ノイズの少ない名詞句の列**は、人間の検索とエージェントの抽出・照合の両方に効く。

## 優先順位（コンフリクト時）

1. **`shopee-product-listing-title.md`**（100 字・構成順・禁止・ユーザー商品名との整合）に違反しない。
2. 本ルーブリックで **誤認・誇張・ノイズ**を減らす。共起語を削る場合は **正本どおり後ろから**（ブランド＋具体名＋カテゴリ短語を優先）。
3. 「SEO 上もっとキーワードを足したい」は、**ソースに根拠がない語**より後回し。

## チェックリスト（内部適用用）

各項目は **該当 / 問題あり / 該当なし** でよい。問題ありなら **必須修正** に落とすか判断する。

### SEO 系

- [ ] **クエリ核**（ブランド・モデル・品目）が左寄せで読み取れるか。無関係語が先頭を占めていないか。
- [ ] **重複・詰め込み**: 同義・近義がスペースの無駄なく畳めるか。キーワードスタッフィングになっていないか。
- [ ] **一貫性**: 表記ゆれ（公式と異なる略号、重複するカテゴリ名）がないか。
- [ ] **100 字**: 1 文字=1 で再カウント済みか（句読点・スペース含む）。

### AEO（エージェント信頼度）系

- [ ] **エンティティ**: 「誰の・どの製品の・何か」が一文で追えるか。
- [ ] **検証**: 調査メモにないスペック・素材・用途を名乗っていないか。
- [ ] **曖昧さ**: 「best」「premium」等、**ソースに裏付けがない一般形容**を減らせるか。
- [ ] **誤結合**: 別商品と混同されそうな語（広すぎるカテゴリ名だけで終わる等）がないか。

### 外部リスト（スプレッドシート等）を参照する場合

- データは **全カ国・全カテゴリが混在**し得る。**当該 SKU の成功要因としては使えない**。
- 使うなら **頻出トークンの参考**にとどめ、**ランキング＝最適タイトルの証拠**としない。
- ファイルはリポジトリの [`reference-data/shopee-trend-sheets/`](../../../../reference-data/shopee-trend-sheets/README.md) に置く運用を推奨（機密・巨大ファイルは Git に含めない）。

## 必須修正の例（非窮尽）

- 調査と矛盾する素材・用途・性別。
- ユーザー Step 1 商品名の意図と矛盾するモデル／品目。
- 100 字超過、またはスタッフィングで可読性が著しく低い。
- 別 SKU と誤認されうるほど名前が欠落している（ブランドのみ等）。

## 任意改善の例

- 冗長なカンマ列をスペースに統一してスロットを節約。
- ソースに現れる **短い**用途語で、後段共起を置き換え。
