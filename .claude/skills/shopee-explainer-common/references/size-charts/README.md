# サイズ情報アセット（シューズ・アパレル中心）

倉庫に置く **ブランド別サイズ表画像** は、**ファイル名でブランド・性別がわかればよい**。  
画像ピクセルの中にロゴやブランド名が写っていなくても構わない。

## 配置（標準）

**`size-charts/` 直下に PNG を並べるだけでよい。** ブランドごとのサブフォルダは **不要**（作らなくてよい）。

命名の例（小文字 ASCII の `brand-slug` を推奨）:

```
size-charts/
  README.md           ← この説明
  keen-mens.png
  keen-womens.png
  salomon-mens.png
  ...
```

| 商品の性別バッジ | 探すファイル名のパターン |
|------------------|---------------------------|
| Men's | `{brand-slug}-mens.png` |
| Women's | `{brand-slug}-womens.png` |
| **Unisex** | **`{brand-slug}-mens.png` を使う**（メンズ表を正とする） |

※ 過去にサブフォルダ形式（`keen/mens.png`）を使っていても動くが、**新規はすべて直下＋ファイル名にブランド**で統一してよい。

## 日本語の表記 → 図解での英語（必須）

- Shopee 図解カードは **英語のみ**。サイズ表のソースが **日本語**（公式 JP・量販 JP・倉庫に保存した JP 表のスクショ）でもよい。
- **Size Guide の HTML 表では、列見出し・注釈を英語に直す**（例: 「センチ／㎝」→ **CM** or **Foot length (cm)**、「対応サイズ」→ **Size**、「履き心地の目安」→ *Fit note* など）。数値はそのまま。
- ブランド固有の日本語説明文は **意味を保ちつつ短い英語**に要約してよい。

## 複数枚のスクショ（表が1枚に収まらないとき）

表が縦長・横長で **1枚のスクショに収まらない場合**は **2枚以上に分割して保存してよい**。

### ファイル名の例（同一ブランド・同一性別）

```
keen-womens-01.png   ← 上側（または左側）
keen-womens-02.png   ← 下側（または右側）
```

連番 `-01` / `-02` / `-03` … でよい（`-part2` でも可）。**性別・ブランドがファイル名からわかること**を優先する。

### 重なり（オーバーラップ）

隣り合うスクショで **数行または数列が被っていてもよい**（読み取りミス防止のための意図的な重複でもよい）。

- **HTML に落とし込むときは、重複する行／列は1回だけ残し、論理的に1つの連続した表として統合する。**
- 数値が微妙に食い違う場合は **より解像度の高いほう／公式に近いほう**を優先し、必要なら脚注で *See brand chart for edge sizes* 程度を付けてよい。

エージェント・作業者は **複数 PNG をすべて読んでから**、最終的な **1 つの英語表**を組み立てる。

## 情報源の優先順位（エージェントがサイズ数値を決めるとき）

理論上の第一位は **各ブランド公式**だが、自動取得は安定しない。**人間が手間をかけて倉庫に保存した画像を実務上の第一優先**とする。

1. **本ディレクトリ直下の `{brand}-mens.png` / `{brand}-womens.png`**（連番 `-01` `-02` など **分割スクショが複数あればすべて**読む。ここから **数値・対応のみ読み取る**）
2. **ブランド公式サイトのサイズ表**（取得できれば最も望ましい。**できれば日本語公式サイト**）
3. **日本の通販サイト**の該当ブランド・該当モデル／カテゴリページ  
   - **ゼビオ（Xebio）**  
   - **アルペングループ（アルペン・スポーツデポ等）**  
   - **ヒマラヤ**
4. **一般的な換算表**（そのブランド専用表がなくてもよい）  
   - 例: **〇〇 cm は US で ○○、UK で ○○、EU で ○○** のような **公開されている対応表**を用いる
5. **S / M / L 等**がどこにもなく、靴長との対応だけが必要な場合などは、文献としての **JIS（身長・胸囲・ウェスト等に基づく体形とサイズ記号）** を **最終手段**として参照し、注釈で *approximate / reference conversion* と明記する

※ 4・5 は **ブランド公式より信頼度が落ちる**ため、可能なら 1〜3 で上書きできる情報を優先する。

## アウトプットの形式（最重要）

- **完成する図解 HTML は、必ず Shopee 図解スキル（Pattern / `base.html` / カードのタイポ・余白）に沿ったコンポーネントであること。**
- 上記 1〜5 はあくまで **数値・サイズ対応を確定するためのソース**。  
- **倉庫 PNG や公式のチャート画像を、そのまま `<img>` で貼ってサイズ欄を代替することはしない**（レイアウト・統一感が崩れるため）。  
- 読み取った内容は **`product-card` 内の Size Guide を、HTML の表（Tailwind・英語見出し）で再構成**する。（ソースが日本語でも **見出しは英語**にすること）
- **`main-image`（800×800）にサイズ表画像を載せる必要はない**。サイズは説明カード側を正とする。

## 適用範囲と免除

- この優先順位・JIS フォールバックは **シューズ・アパレル・サイズ軸が購買判断に効くギア**を想定している。
- **キャンプギアのようにサイズ表が本質でない商品**では **融通してよい**。  
  - 該当しない場合は **Size Guide セクションを省略**してよい（冗長な一般換算を載せない）。

## 著作権・更新

- 公式・量販サイトのスクショは各サイト・ブランドの規約に従う。  
- 必要なら直下に `SOURCES.md` を置いて **ファイル名 → 取得元 URL・日付** を1行ずつメモすると更新が楽。
